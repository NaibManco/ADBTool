# 模块文档维护规约

> 父文档：[AGENTS.md](../../AGENTS.md)——本文件是 `docs/modules/` 全部文档的维护规则。

## 谁在什么时候改

文档与代码同变更、同提交（本仓库无 git，即同一次会话完成），**不留"回头补文档"**——回头即永不。具体触发点：

| 变更类型 | 必须同步的文档动作 |
|---|---|
| 新增功能模块 | 新建 `docs/modules/<module>.md`（用现有文档的固定结构），AGENTS.md 索引树加一行，目录职责节加文件条目 |
| 修改某模块的行为/数据流/IPC | 改对应 `docs/modules/<module>.md` 的「关键链路」「数据流」「IPC」小节 |
| 修改共享类型 / AndroidToolApi | 改 `shared-types.md`（含方法分区表）；事件通道增删也要同步 |
| 调整全局约定（安全边界、验证原则、打包方式等） | 改 AGENTS.md；模块文档只在模块级受影响时改 |
| 修 bug 引入了新的"必须知道"事实（陷阱、竞争、协议语义） | 追加到对应模块文档的「约定」或「已知边界」，**在代码里留注释的同时文档也要有**——代码注释给读代码的人，文档给下次开工的人 |
| 删除/移除功能 | 删对应文档小节或整个文件；AGENTS.md 功能清单同步（历史教训：音量键移除后功能清单没同步，靠后来发现） |
| 改版本号/产物名 | AGENTS.md 的版本号、产物路径 |

## 修改顺序（写代码时）

1. 动手前：先读将改的 `docs/modules/<module>.md` + `shared-types.md`（这就是这套文档存在的意义——替代重新读代码考古）。
2. 写代码。
3. 完成后、宣告"完成"**之前**：按上表同步文档。验证清单里有这一步。

## 写作规则

- **只写当前为真的事实**，不写计划、不写"将来可以"（那些放代码 TODO 或对话里）。
- 数字断言（上限、超时、版本号、退出码）必须与代码一致；文档写 `MAX_ENTRIES = 50_000` 这类值时要能对上源码常量。改这些常量时全局搜文档。
- 结构统一：`职责 → 文件 → 关键链路/数据流 → IPC（如有）→ 约定 → 已知边界 → 测试`。新文档照抄这个骨架。
- 每份文档头部保留 `> 父文档` 链接和相关模块链接。
- 中文，与代码注释语言一致。

## 一致性巡检（低成本方式）

- 不搞定期巡检。防腐靠两条：① 改动时顺手同步（上表）；② 每次会话开始读到与代码矛盾的文档时，**当场修正文档**（发现即修，不攒）。
- 判断文档过时的信号：模块文档描述的文件/函数/常量在代码里搜不到（grep 一下），或行为描述与代码明显冲突。以代码为准，改文档。

## AGENTS.md 与模块文档的边界

- AGENTS.md：全局成立的事（进程安全边界、命令构造原则、验证原则、打包流程、索引树、功能一览）。
- 模块文档：只在该模块内成立的事。
- 冲突时以模块文档为准（更细、更新），发现冲突要把 AGENTS.md 一并改掉，不允许长期分歧。
